## 摘要
使用多智能体强化学习训练基于LLM的多智能体系统正迅速受到关注，而一条并行的工作线主张这类系统应以其行为而非仅凭奖励来评判。我们在空间合作游戏中同时探讨这两方面，在游戏中，以低层动作提示的小型冻结LLM会彻底失败，获得零奖励。在选项/半MDP框架的指导下——并且由于选项执行在智能体间是异步的，其在宏动作Dec-POMDP中的多智能体扩展——我们为每个游戏配备了一个符号化\emph{选项}库：由符号化规划器执行的类型化、状态可行、短视域行为。每个库由前沿编码模型根据游戏源代码起草；然后，通过廉价的随机策略预烧录轨迹机械地综合出过滤每个菜单的可行性守卫——只有在守卫能解释重复执行失败且不隐藏任何已记录的成功时，该守卫才会被采用——因此没有任何守卫是手工编写、选择或奖励调优的。每个智能体的LLM充当其选项上的策略，具有由多智能体GRPO的每智能体变体（PA-MAGRPO）训练的私有每智能体LoRA适配器；这将冻结基础模型从零奖励提升到在三个游戏和四个小型骨干网络上的胜任表现。随后，行为审计显示奖励与合作脱钩：上升的奖励曲线可能仅仅意味着一个智能体学会了独自完成整个任务，而其伙伴闲置——只有当任务使合作成为必要时，合作才会出现。因此，仅凭奖励是合作不可靠的读数；行为评估必须与奖励评估并置。

## Abstract
Training LLM-based multi-agent systems with multi-agent reinforcement learning is rapidly gaining traction, and a parallel line of work argues that such systems should be judged by their behavior, not only their reward. We take up both threads in spatial cooperative games, where small frozen LLMs prompted with low-level actions fail outright, earning zero reward. Guided by the options/semi-MDP framework---and, because option execution is asynchronous across agents, its multi-agent extension in macro-action Dec-POMDPs---we equip each game with a library of symbolic \emph{options}: typed, state-feasible, short-horizon behaviors executed by a symbolic planner. Each library is drafted by a frontier coding model from the game's source code; the feasibility guards that filter each menu are then synthesized mechanically from cheap random-policy burn-in rollouts---a guard is adopted only if it explains repeated execution failures while hiding no logged success---so no guard is authored, selected, or reward-tuned by hand. Each agent's LLM acts as its policy over options, with a private per-agent LoRA adapter trained by a per-agent variant of multi-agent GRPO (PA-MAGRPO); this lifts frozen bases from zero reward to competent play across three games and four small backbones. Behavioral audits then reveal that reward and cooperation decouple: a rising reward curve may simply mean that one agent has learned to run the entire task alone while its partner idles---cooperation emerges only when the task makes it necessary. Reward alone is thus an unreliable readout of cooperation; behavioral evaluation must sit alongside it.

## 1. 论文的核心问题与整体含义

**研究动机**：基于LLM的多智能体系统的训练越来越受关注（如MAGRPO、CORY等），但这类系统不应仅以奖励评估，而应关注实际行为。同时，在空间合作博弈中，直接用低层动作界面（如上下左右、交互）提示小型冻结LLM会导致完全失败——模型无法可靠地将高层目标转化为原始动作，产生"空间幻觉"和"模式坍缩"，获得零奖励。

**核心问题**：如何将小型（2–4B参数）LLM训练为空间多智能体协作策略？训练成功后，奖励曲线的上升是否真正意味着协作涌现？

**整体含义**：作者发现**奖励与合作可能解耦**——高奖励可能仅源于单一智能体独跑任务，而非团队协作；反过来，近乎平坦的奖励曲线也可能隐藏重要的可持续行为转变。因此行为评估必须与奖励并列。

## 2. 方法论

### 核心思想

以**符号化选项库（symbolic option library）** 作为中介接口，将LLM的决策空间从原始低层动作提升到语义化、短视界的宏动作；配合**逐智能体私有LoRA适配器**与**逐智能体变体的MAGRPO（PA-MAGRPO）** 进行强化微调。

### 关键技术细节

1. **形式化框架**：
   - 底层博弈建模为Dec-POMDP；
   - 每个智能体配备固定选项集 \(Z_i\)，决策发生在选项边界，单个智能体的问题转为半MDP；
   - 因选项在不同智能体间异步起止，团队级问题建模为**宏动作Dec-POMDP**；
   - LLM在每个决策点从状态过滤后的可行菜单 \(Z_i(o_i^t)\) 中选择一个选项，执行由符号规划器完成。

2. **阶段1：前端模型起草选项库**（唯一的模型介入步骤）：
   - 将游戏源代码输入Claude Opus 4.8，生成类型化选项模式，每个选项带四部分契约：实例化条件、执行器、终止条件、**效果谓词**（后置条件）。
   - 执行器刻意"环境天真"，只含算法展开所需的最少检查（如路径规划需要目标），环境合法性知识留给守卫合成阶段自动发现。
   - 效果谓词采用delta形式，绑定到执行代理的私有状态转换上，防止共享状态误归属。

3. **阶段2：均匀随机烧录（uniform burn-in）**（无LLM）：
   - 用均匀随机策略在无守卫菜单上运行数百集，记录每个选项执行的结果（成功/效果失败/显式失败），无GPU，速度快（约55万次决策仅需约70秒/单核CPU）。
   - 对照实验表明：均匀随机策略获得36条守卫，而冻结LLM策略仅2条且成本约400倍——验证均匀烧录策略的必要性。

4. **阶段3：自动守卫合成**：
   - **显式通道**：类型化失败原因出现≥5次直接转为守卫（如NoPath→可达性检查）。
   - **推断通道**：所有1-和2-字面量合取项，若覆盖≥5次失败且**零覆盖成功**（"纯度"验收证书），即被采纳为守卫。
   - 纯成功合取项被拒绝，防止策略性知识混入守卫集；覆盖成功案例（如临时延展执行中前置条件途中达成）也被拒绝。

5. **阶段4：菜单组装**：
   - 每个目标类实例化一条菜单项目（非仅最近目标）；
   - 对每个实例的读集特征评估所有采纳合取项，命中即隐藏；
   - 每次决策用种子化RNG打乱菜单字母顺序，防止字母A先验被模型利用。

6. **训练算法（PA-MAGRPO，算法1）**：
   - 每轮收集K条并行的联合轨迹；
   - 每条轨迹用**共享团队回报**\(R_k\)评分；
   - 在cohort内归一化得到共享的组相对优势 \(\hat{A}_{k,t} = (R_k - \mu)/\sigma\)（所有智能体同一优势值）；
   - 每个智能体仅在自己的选项决策上（\((o^i_{k,t}, z^i_{k,t})\)）执行PPO截断更新，加KL惩罚；
   - 仅更新该智能体的私有LoRA适配器；基础模型冻结共享。

## 3. 实验设计

### 场景 / 基准

- **Melting Pot Cleanup**（clean_up子基板）：7智能体、150步/集。共享河流需清理，苹果在污垢低时生长——序贯社会困境。
- **Overcooked-AI**：2智能体、400步/集，两个分离厨房布局：
  - **Asymmetric Advantages (AA)**：两厨师各占半厨房，但各自可独立完成全部流程——协调可选；
  - **Forced Coordination (FC)**：任何一边无法独自完成汤品，必须柜台递交接力——协调强制。AA/FC构成**组内控制对**。
- **Commons Harvest**（commons_harvest_no_thinning子基板）：7智能体、400步/集。共享6个苹果补丁，耗尽即永久破坏——公共池塘资源困境。

## 6. 主要结论与发现

1. **完整配方有效**：冻结基座在三个游戏均为0奖励；全方法在四骨干 × 五种子下均获得正回报（Cleanup 60.25–105.69、Overcooked AA 6.21–7.31、Harvest 85.41–115.52）。
2. **两个成分缺一不可**：选项菜单解决"接地失败"和"地平线压缩"，私有LoRA解决"角色分化失败"。
3. **原生动作RL无法修复吸引子**：MAGRPO直接在原始字母上训练会锐化已有退化模式（FIRE_CLEAN从95.8%升至98.4%），且使cohort方差塌缩、更新无信号。
4. **共享LoRA无法容纳角色分化**：单适配器不能同时表达"清洁者"和"食者"两个角色，清洁训练曲线出现短暂峰值后回退（0.10±0.45 vs 全法93.25）。
5. ****奖励与协作解耦（双向）**：
   - Cleanup：高奖励伴随真实的角色分工（3食者3清洁者1助手）；
   - Overcooked AA：高奖励但无协调——智能体0约69%时间装洋葱、智能体1约72%时间等待，零交接；单独放置仍可交付（solo-solvable）；
   - Overcooked FC：去掉solo解后训练达7.57交付，单独放置为0——合作仅任务强制时出现；
   - Commons Harvest：奖励曲线近似平坦（76.63→95.68），但补丁存活从~0提高到~2.5/6持续至400步——**奖励曲线低估了合作**。
6. **选项菜单的约束性选择**（而非自由JSON生成）是角色专业化涌现的必要条件：Ablation D（compound-JSON）无法分化角色，所有适配器都吃苹果且主食者随机漂移。

## 7. 优点

1. **清晰的模块化设计**：前端模型仅参与一次库起草；守卫合成完全机械化、无人工参与、无奖励调优——可复现、可审查。
2. **"纯度"证书的设计巧妙**：拒绝任何覆盖成功执行的合取项，从机制上排除策略性知识进入守卫集，保证守卫只编码"执行有效性"而非"策略"。
3. **形式化匹配严谨**：选项→半MDP、异步选项→宏动作Dec-POMDP、更新仅发生在选项边界——理论账目清楚，无需半MDP折扣机制即可训练。
4. **行为审计有价值**：不仅报告奖励，还报告逐智能体宏分布、访问热力图、补丁存活、solo测试——实证揭示奖励与协作解耦，对社区有方法论启示。
5. **反直觉的失败模式刻画真实细致**：对"空间幻觉"和"模式坍缩于安全默认"给出了完全可复现的逐字追踪证据。

## 8. 不足与局限

1. **规模与泛化有限**：仅覆盖≤4B模型与三个空间博弈；大模型或非空间任务未测试；选项库逐游戏手工构建（即使由LLM起草），缺乏选择选项空间的系统化方法。
2. **算力信息不完整**：未报告端到端训练时长、GPU小时数、最优检查点选择的评估代价，对可复现性和成本判断有影响。
3. **消融套件的统计强度有限**：单训练种子，21–22行虽给出95% CI，但未反映接口采样与初始化变异；角色分配结论仅在一个种子上验证。
4. **评估窗口有限**：行为审计（图表）只呈现一个训练种子的轨迹，跨种子行为变异未量化。
5. **潜在偏差风险**：前端模型输出的不可种子化——库的抽样虽随机化，但每次运行只抽一次库，无法完全排除某一特定库的主导影响；AA的"合作缺失"可能是布局本身激励机制的结果，对FC对照的"非solo可解"假设依赖较强。
6. **未解决理论问题**：奖励与协作解耦的结论是行为证据而非一般化理论；具体角色分配检查仅一个种子；选项库的每个种子抽样意味着不同种子面对的其实是不同的动作空间——这为跨种子比较引入了额外混淆变量。
7. **训练配置无交叉验证**：超参按环境固定选择自小型试运行，未系统遍历；结果可能依赖这些选定的超参。
