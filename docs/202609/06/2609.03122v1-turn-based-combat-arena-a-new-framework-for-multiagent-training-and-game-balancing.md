## 摘要
本文是关于回合制战斗竞技场系列论文中的第一篇，该竞技场是一个可配置的回合制策略游戏框架，旨在支持机器学习智能体的高效训练与评估。所提出的框架允许灵活修改游戏规则和参数，从而能够在多种场景下进行快速实验。其架构针对高吞吐量模拟进行了优化，支持每秒数万局游戏，并能在单台机器上存储和处理数十亿条游戏记录。本文详细研究了游戏平衡问题，特别是游戏单位的参数平衡。我们评估了几种优化方法，并表明多种方法收敛到类似的解，这表明在识别平衡的游戏配置方面具有鲁棒性。这些结果表明，该框架可以作为一个实用的平台，既用于游戏设计分析，也用于智能体训练。

## Abstract
This paper is the first in a series on Turn-Based Combat Arena, a configurable framework for turn-based strategy games designed to support the efficient training and evaluation of machine learning agents. The proposed framework enables flexible modification of game rules and parameters, allowing rapid experimentation across diverse scenarios. Its architecture is optimized for high-throughput simulation, supporting tens of thousands of games per second and enabling the storage and processing of billions of gameplay records on a single machine. The problem of balancing the game, and particularly the parameters of game units, is investigated in detail. We evaluate several optimization approaches and show that multiple methods converge to comparable solutions, suggesting robustness in identifying balanced game configurations. These results indicate that the framework can serve as a practical platform for both game design analysis and agent training.

## 1. 核心问题与研究动机

- **研究背景**：从1990年代 Chinook 击败跳棋世界冠军开始，游戏长期作为 AI 演进的试验场。从 DeepBlue、AlphaGo 到 AlphaZero，游戏 AI 的发展经历了从依赖人类棋谱与树搜索，到纯粹基于自对弈和强化学习的范式转变。然而，现代大型商业游戏状态空间近乎无穷且机制高度复杂，使得研究基础战略行为规律异常困难。
- **核心问题**：现有回合制策略游戏研究平台（如 TUBSTAP、STRATEGA、ADAPTA）存在明显的空白：
  1. 难以兼顾**高吞吐量仿真**与灵活的**规则/参数配置**；
  2. 缺乏对游戏平衡（特别是单位参数平衡）的**系统化数学定义与优化方法**；
  3. 已有研究多集中于战胜人类顶尖选手，忽视了游戏平衡性、策略多样性、玩家行为复杂度等同样根本性的开放问题。
- **研究意义**：该论文作为系列研究的第一篇，旨在构建一个简单但足够复杂、可灵活配置的回合制战斗框架，既可支撑从简单（暴力搜索可解）到复杂（需先进ML方法）的游戏复杂度谱系研究，也为多智能体强化学习（MARL）提供高效训练环境与游戏平衡性优化基础。

## 2. 方法论：核心思想与关键技术

### 2.1 游戏规则设计（TBCA）
- **总体定位**：灵感源自《英雄无敌》（Heroes of Might and Magic）的战斗系统，并大幅简化至接近《Forge of Empires》的网页游戏风格。游戏为零和对抗性博弈，目标为消灭对方全部单位。
- **游戏几何与玩家**：N×M 矩形战场（本研究中 N=M=20），正交相邻距离为 1，对角相邻距离为 1.5；两队（A/B）各含 T=8 个单位，初始按确定性/随机位置排列。
- **单位类型**：5 种可配置单位——轻型（L，近战）、重型（H，近战慢速高防）、快速（F，骑兵）、短程（SR，弓箭手）、长程（LR，攻城器）。关键战术参数如下：
  - 攻击范围 AR + 移动点数 MP 固定为：L(1,12)、H(1,5)、F(1,17)、SR(7,5)、LR(17,2)——此配置使军队能相互"克制"，如 F 的速度确保 LR 无法安全远程消耗。
- **伤害机制**（公式1）：DM = ⌊DM₀·A(A,D)·R⌋
  - 基准伤害 DM₀ = H/3.5（保证单位存活约3.5次攻击）；
  - 攻防修正 A(A,D) = 1 + (A−D)/50，A,D 取值范围均为 0~30，使修正系数落在 0.4~1.6 范围；
  - 随机因子 R = 1 + α·rnd(−1,1)，α=0.1，引入 0.9~1.1 的伤害波动。
- **行动顺序机制**：区别于 TUBSTAP 的整队轮流行动，TBCA 以单位移动点数（MP）确定行动优先级（MP 高者先行动），相同 MP 则随机排序——避免任何一方先手偏见。每回合只能执行一个行动（跳过、移动、攻击、或移动后攻击），攻击后若目标存活且在攻击者范围内可反击（反击伤害减半）。
- **和棋机制**：为避免无限循环（对 ML 训练尤其有害），超出"空闲回合"阈值即判平局。

### 2.2 状态空间复杂度推导
- 采用 stars-and-bars 组合公式计算全部单位的健康状态组合数（死=0），结合队伍数平方及棋盘排列（NM)!/(NM−2T)!，推得状态复杂度 C ≈ 3.62×10⁶⁰，**高于国际象棋（10⁴³）**，介于 Hex（10⁵⁷）和 Thurn and Taxis（10⁶⁶）之间。同时该复杂度可通过调节 H、类型数、队伍大小灵活调整。

### 2.3 系统架构（高吞吐设计）
- **Battle Engine（战斗引擎）**：设计为无状态，支持并行多线程运行，实现单机约 **55,000 局/秒**（≈6×10⁶ 状态/秒，每局平均约 120 个状态）。
- **数据库层**：采用 DuckDB 列式 OLAP 存储，单机能高效处理 **3~4 亿条记录**（约 100GB 磁盘）。
- **内存暂存层（In-memory stage）**：弥补列式存储频繁更新能力弱的缺陷，先累积战斗统计再按计划批量写入数据库。
- **Battle API**：基于实时 WebSocket，为任意 AI 智能体提供标准化的 JSON 状态输入、动作输出接口，并支持可选的 "label" 字段（可关联每步决策的策略标签），内置多种基于规则的战斗智能体与外部 AI 完全可互换。

### 2.4 平衡性指标（Loss 函数族）
论文提出了多层次的平衡衡量体系：
- **同类队伍成对对决矩阵**：对 5 类单位两两组队成对博弈，统计平均击杀率 k_ij，构建非对称空洞矩阵，从此派生：
  - *k₂*：每类单位平均击杀率（及被杀率）应向全局均值 κ 靠拢的归一化均方误差；
  - *k₂₀*：更严格的逐项平衡均方误差（要求任意 k_ij → κ）。
  - 对应可换用伤害量 d_ij 得到 *d₂*、*d₂₀*。
- **半随机队伍成对对决矩阵（k′₂, k′₂₀, d′₂, d′₂₀）**：每队固定 5 个单位（每种类型各1个），其余 (T−5) 个单位全为指定类型，以捕捉**单位间的相互作用**（如 H 吸引火力保护 LR）。
- **战斗级指标**：幸存单位数 n 的 MSE σₙ；总行动数 a 的归一化 MSE εₐ（旨在抑制"一边倒"的短促战斗）。
- **单位类型特异性指标**：各类型存活率 sᵢ 的 MSE σₛ；获胜影响力指标 wᵢ（获胜队伍中各类单位的初始数量，理想值为 T/5=1.6）的方差 σ_w。

### 2.5 平衡优化问题的形式化
- 将平衡问题转成**10维参数优化问题**（5类型 × 2属性[攻击A+防御D]），每个参数为 0~30 的整数（取值空间 31¹⁰）。
- 采用 **CMA-ES（协方差矩阵自适应进化策略）** 算法：因原始问题为离散整数域而 CMA-ES 面向连续域，故优化过程以连续变量处理、最终评估时四舍五入取整。

## 6. 主要结论与发现

- **框架性能达标**：TBCA 架构单机即可支撑每秒数万局模拟并高效存取海量对局记录，满足训练大规模 RL 模型的数据生产要求。
- **跨损失函数的强一致性**（表1、表2）：
  1. 不同损失函数求得的参数值并非散乱，而是趋于相似/相关的区域：k₂ 与 k₂₀、k′₂ 与 k′₂₀ 两类自然相似；基于胜利影响力调优的 σ_w 与半随机队伍设定的 k′₂₀ 高度一致，显著性在多种伤害函数和战术参数变更中依然保持；
  2. **共性规律**：无论采用何种损失函数，最优平衡总要求 F 与 SR 的攻击值最高、LR 的攻击最低、H 的防御较高而 SR 防御相对低——这反映了单位的战术属性（AR 和 MP）被数值补偿的系统恒性；
  3. σ_w 平衡导向的是多样化的单位参数，而诱导 L、H 攻击/防御高达 29、F 防御偏低等。
- **可行与不可行的平衡目标**：
  - **可达成平衡**：以半随机队伍的比较或胜利影响力 σ_w 为损失可轻松收敛；k₂ 类亦能收敛；
  - **本质上不可行/无效的目标**：严格的逐对击杀平衡 k₂₀ 无法实现（最优也高达 0.462），存活率跨单位一致 σₛ 违背了不同兵种战术功能分化的内在"快单位易阵亡、远程单位更易存活"的逻辑，不适合作为唯一平衡目标；
  - σₙ 和 εₐ 不适合直接作为优化 loss，但可作**平衡好坏的定性指标**（数值大代表可能失衡）。
- **推荐实践**：先谨慎设定伤害函数与战术参数（制约可达平衡空间），再以最小化获胜影响力 MSE σ_w（或半随机队伍类指标）作为优化目标是稳定可靠的选择。

## 7. 优点

- **架构设计精巧**：无状态并行引擎 + 内存批量写入 + 列式数据库 + WebSocket 标准化 API 的组合，使系统在生产环境切实具备支撑数十亿数据记录与外部 ML 模型接入的工程能力。
- **问题形式化程度高**：将模糊"游戏平衡"概念展开为 6 类严格数学损失函数家族，并首次系统揭示不同平衡定义之间的关系与冲突（哪些目标彼此等价/互斥）。
- **严谨统计报告**：对每项指标明确给出置信度0.95下的误差上界，并如实暴露 d₂ 系列指标 25% 的方差问题。
- **启发式强**：发现胜负影响指标（σ_w）不依赖人为假设的团队组成假设且与其他指标高度一致，对实际游戏平衡工作具有很强的指导意义。从"试错经验调参"上升到"可复现最优参数"层面。
- **兼容多个复杂度梯度**：状态空间可调（10⁰~10⁶⁰+），一座框架即可衔接简单可解博弈到复杂需先进深度的 MARL 场景。

## 8. 不足与局限

- **智能体与训练场景单一**：平衡寻优仅基于一个简单规则的启发式贪心 agent，不能保证对更高水平（尤其 DRL/自对弈）的 agent 仍保持平衡——在多智能体 RL 中纳什均衡意义上的平衡才是最终目标，本文尚未触及。
- **未报告寻优算力开销**：缺乏 CMA-ES 代数、各损失函数总 CPU 时间等关键训练数据，削弱了读者对方法落地成本和可复现性的判断。
- **损伤指标的可靠性缺陷**：损伤类指标（d₂）误差上限达 25%（纵使 500万局也压不住方差），严重制约其作为 loss 的实际可用性——但作者仅在后续做了相关性说明，并未给出有效降方差手段。
- **离散化耦合问题**：连续 CMA-ES 优化完成后四舍五入取整的方案可能会让最终收敛点与整数域真实最优产生偏差；同时未与其他离散进化算法（如遗传/贝叶斯优化）对比，无法说明该框架在当前任务上的算法优越性。
- **实验未能完整放开参数空间**：只对攻击/防御做平衡、固定了单位种类战术参数的设定，未探索地形/移动/射程间的交互平衡；对启发式智能体的规则多样性也未做敏感性测试；
- **缺少基准框架（如 STRATEGA、TUBSTAP）的横向系统测量比较**：无法据此得出该框架较现有方案在训练效率与灵活性上的定量优势结论。
